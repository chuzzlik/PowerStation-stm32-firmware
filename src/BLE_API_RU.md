# Bluetooth API зарядной станции PowerBank

Версия API: **5**  
Версия прошивки: **2.5.1-ble-api**

## 1. Общая схема

Устройство рекламируется с именем:

```text
PowerBank
```

Bluetooth включается долгим нажатием кнопки переключения экранов, когда станция включена. При программном выключении станции Bluetooth отключается.

Передаваемые строки:

- команды — обычный текст UTF-8 без завершающего перевода строки;
- ответы и телеметрия — JSON в UTF-8;
- имена команд и полей чувствительны к регистру;
- десятичный разделитель — точка.

Сервер запрашивает MTU `517`. Клиенту также желательно запросить/принять MTU 517 до подписки на уведомления, поскольку JSON телеметрии и настроек может быть значительно больше стандартных 20 байт полезной нагрузки.

## 2. UUID

### Сервис

| Назначение | UUID |
|---|---|
| PowerBank Service | `6f2a0001-5a3d-4e2c-9a73-1b21d9b00001` |

### Характеристики

| Назначение | UUID | Свойства |
|---|---|---|
| Статус, результаты команд и ошибки | `6f2a0002-5a3d-4e2c-9a73-1b21d9b00001` | Read, Notify |
| Команды | `6f2a0003-5a3d-4e2c-9a73-1b21d9b00001` | Write, Write Without Response |
| Настройки | `6f2a0004-5a3d-4e2c-9a73-1b21d9b00001` | Read, Notify |

Статус автоматически отправляется раз в **1 секунду**, пока клиент подключён и подписан.

Настройки можно прочитать напрямую из характеристики настроек. После успешной команды `set` прошивка обновляет её значение и отправляет уведомление с полным актуальным набором настроек.

## 3. Рекомендуемая последовательность подключения

1. Найти устройство `PowerBank` и подключиться.
2. Согласовать MTU 517, если API платформы это позволяет.
3. Найти сервис и три характеристики.
4. Подписаться на уведомления характеристик статуса и настроек.
5. Прочитать обе характеристики или отправить команду `get all`.
6. Разбирать JSON по полю `type`.

## 4. Телеметрия `status`

Пример:

```json
{
  "type": "status",
  "apiVersion": 5,
  "firmwareVersion": "2.5.1-ble-api",
  "systemState": "ON",
  "powerState": "DISCHARGE",
  "socPercent": 76.42,
  "voltageV": 12.841,
  "currentA": -4.218,
  "powerW": -54.164,
  "averagedPowerW": -51.732,
  "currentStoredWh": 343.890,
  "learnedCapacityWh": 450.000,
  "estimatedTimeHours": 6.650,
  "learningActive": true,
  "learningDischargeWh": 106.110,
  "learnedCycles": 2,
  "mosfetEnabled": true,
  "bluetoothEnabled": true,
  "bluetoothConnected": true
}
```

### Поля телеметрии

| Поле | Тип | Описание |
|---|---:|---|
| `type` | string | Всегда `status` для телеметрии. |
| `apiVersion` | integer | Версия структуры BLE API. Сейчас `5`. |
| `firmwareVersion` | string | Версия прошивки. |
| `systemState` | string | `ON` — станция включена; `OFF` — программно выключена. |
| `powerState` | string | `CHARGE`, `DISCHARGE` или `IDLE`. |
| `socPercent` | number | Текущий расчётный остаток заряда, %. Это также читаемое значение для команды `set remainingPercent=...`. |
| `voltageV` | number | Напряжение аккумуляторной сборки, В. |
| `currentA` | number | Ток, А. Положительный — зарядка, отрицательный — разрядка. |
| `powerW` | number | Мгновенная мощность, Вт. Положительная — зарядка, отрицательная — разрядка. |
| `averagedPowerW` | number | Усреднённая мощность для расчёта ETA. Знак такой же, как у `powerW`. |
| `currentStoredWh` | number | Расчётное количество энергии, оставшееся в аккумуляторах, Вт·ч. |
| `learnedCapacityWh` | number | Текущая обученная ёмкость, Вт·ч. |
| `estimatedTimeHours` | number | Время до полного заряда или разряда, часы. Значение `-1` означает, что ETA сейчас недоступно. |
| `learningActive` | boolean | Идёт ли цикл обучения ёмкости. |
| `learningDischargeWh` | number | Сколько энергии уже отдано в текущем цикле обучения, Вт·ч. |
| `learnedCycles` | integer | Количество завершённых циклов обучения. |
| `mosfetEnabled` | boolean | Фактическое логическое состояние выходного MOSFET. |
| `bluetoothEnabled` | boolean | BLE включён и устройство рекламируется либо обслуживает соединение. |
| `bluetoothConnected` | boolean | Есть активное BLE-соединение. |

## 5. Настройки `settings`

Пример:

```json
{
  "type": "settings",
  "apiVersion": 5,
  "nominalCapacityWh": 450.000,
  "lowCutVoltageV": 9.800,
  "fullVoltageV": 14.200,
  "fullCurrentA": 0.150,
  "chargeEfficiency": 0.950,
  "lowSocPercent": 15.00,
  "criticalSocPercent": 3.00,
  "learningEndVoltageV": 10.400,
  "learningMinDischargeWh": 50.00,
  "learningCorrectionAlpha": 0.250,
  "powerLimitW": 120.00,
  "etaAveragingSeconds": 45.0,
  "etaIdleHoldSeconds": 15.0,
  "etaMinPowerW": 3.00,
  "etaMaxHours": 168.00,
  "smallScreenTimeoutSec": 30,
  "mainScreenTimeoutSec": 30
}
```

### Изменяемые конфигурационные поля

Все допустимые команды `set` автоматически сохраняются в NVS. Значение за пределами диапазона не отклоняется, а ограничивается ближайшей границей. Поэтому после записи приложение должно использовать значение из уведомления `settings` или следующего `status`, а не считать, что переданное число применилось без изменения.

| Ключ `set` | Диапазон | По умолчанию | Описание |
|---|---:|---:|---|
| `nominalCapacityWh` | 1…5000 Вт·ч | 450 | Паспортная/опорная ёмкость. Сейчас используется как отдельное справочное значение и отображается на экране настроек; автоматически не заменяет обученную ёмкость. |
| `lowCutVoltageV` | 1…60 В | 9.8 | Порог аварийного отключения по низкому напряжению. Во время зарядки защита не отключает станцию. |
| `fullVoltageV` | 1…60 В | 14.2 | Минимальное напряжение для определения полного заряда. Используется вместе с `fullCurrentA`. |
| `fullCurrentA` | 0.01…20 А | 0.15 | Максимальный модуль тока для определения завершения зарядки. |
| `chargeEfficiency` | 0.50…1.00 | 0.95 | Коэффициент, применяемый при подсчёте принятой энергии и ETA зарядки. |
| `lowSocPercent` | 0…100 % | 15 | Порог индикации низкого заряда светодиодом. Сам по себе станцию не выключает. |
| `criticalSocPercent` | 0…100 % | 3 | Порог аварийного выключения станции по расчётному остатку. |
| `learningEndVoltageV` | 1…60 В | 10.4 | Напряжение завершения обучающего разряда. |
| `learningMinDischargeWh` | 1…5000 Вт·ч | 50 | Минимальная отданная энергия, необходимая для завершения обучения. |
| `learningCorrectionAlpha` | 0.01…1.00 | 0.25 | Доля нового измерения в коррекции ёмкости. `0.25` означает 25% нового измерения и 75% прежнего значения. |
| `powerLimitW` | 5…2000 Вт | 120 | Порог аварийного отключения по модулю мощности при разрядке. |
| `etaAveragingSeconds` | 5…300 с | 45 | Постоянная времени EMA-фильтра мощности для ETA. Большее значение делает ETA стабильнее, но медленнее реагирует. |
| `etaIdleHoldSeconds` | 0…120 с | 15 | Сколько сохранять усреднение и ETA во время кратковременного перехода в `IDLE`. |
| `etaMinPowerW` | 2…100 Вт | 3 | Минимальная мощность, при которой рассчитывается ETA. Нижняя граница равна системной мёртвой зоне 2 Вт. |
| `etaMaxHours` | 1…1000 ч | 168 | Максимальное отображаемое/передаваемое ETA. |
| `smallScreenTimeoutSec` | 5…3600 с | 30 | Тайм-аут выключения маленького экрана в простое. Передавать целое число. |
| `mainScreenTimeoutSec` | 5…3600 с | 30 | Тайм-аут выключения большого экрана. Передавать целое число. |

Прошивка пока не проверяет логические отношения между разными полями. Например, она не запрещает установить `criticalSocPercent` выше `lowSocPercent` или `lowCutVoltageV` выше `fullVoltageV`. Такие проверки следует выполнять в приложении.

## 6. Изменяемые значения состояния

Следующие значения тоже изменяются командой `set`, но являются текущим состоянием аккумулятора, а не обычной конфигурацией. Их актуальные значения передаются в `status`.

| Ключ `set` | Диапазон | Читаемое поле | Описание |
|---|---:|---|---|
| `learnedCapacityWh` | 50…1000 Вт·ч | `status.learnedCapacityWh` | Принудительно установить обученную ёмкость. Текущий запас энергии ограничивается новой ёмкостью. |
| `currentStoredWh` | 0…`learnedCapacityWh` | `status.currentStoredWh` | Принудительно установить текущий запас энергии. |
| `remainingPercent` | 0…100 % | `status.socPercent` | Удобный псевдопараметр: прошивка пересчитывает `currentStoredWh = learnedCapacityWh × percent / 100`. Отдельного хранимого поля `remainingPercent` нет. |

Таким образом, для каждого доступного ключа `set` существует передаваемое текущее значение: конфигурация читается через характеристику настроек, а три значения состояния — через характеристику статуса.

## 7. Команды

Команды записываются в характеристику команд.

### Чтение

| Команда | Результат |
|---|---|
| `status` или `get status` | Немедленное уведомление `status`. |
| `settings` или `get settings` | Немедленное уведомление `settings` через характеристику настроек. |
| `all` или `get all` | Уведомления `settings` и `status` через соответствующие характеристики. |

### Изменение параметра

Формат:

```text
set key=value
```

Примеры:

```text
set powerLimitW=150
set etaAveragingSeconds=60
set remainingPercent=80
set smallScreenTimeoutSec=45
```

Пробелы вокруг ключа и значения удаляются. Максимальная длина команды — 127 байт.

### Служебные команды

| Команда | Действие |
|---|---|
| `save` | Принудительно сохранить текущее состояние и конфигурацию. Обычная успешная команда `set` и так сохраняется сразу. |
| `markFull` | Установить запас энергии равным обученной ёмкости, снять блокировку защиты и запустить цикл обучения, если он ещё не активен. |
| `resetLearning` | Остановить текущий цикл обучения и очистить данные последнего измерения/коррекции. Общий счётчик завершённых циклов и накопленные энергетические счётчики не обнуляются. |

## 8. Результаты команд

Успех:

```json
{
  "type": "result",
  "command": "set powerLimitW=150",
  "ok": true
}
```

Ошибка:

```json
{
  "type": "result",
  "command": "set unknown=1",
  "ok": false,
  "error": "unknown_setting"
}
```

Возможные значения `error`:

| Ошибка | Причина |
|---|---|
| `empty_command` | Получена пустая команда. |
| `unknown_command` | Команда не поддерживается. |
| `expected_key_equals_value` | После `set` нет корректной конструкции `key=value`. |
| `empty_value` | Значение после `=` отсутствует. |
| `invalid_number` | Значение не является конечным числом. |
| `unknown_setting` | Неизвестный ключ настройки. |
| `response_too_large` | Сформированный JSON превысил внутренний лимит 500 байт. |

## 9. Синхронизация состояния в приложении

После подключения приложение должно хранить два независимых объекта:

- последний `status` — быстро меняющаяся телеметрия и состояние;
- последний `settings` — пользовательская конфигурация.

После команды `set`:

1. дождаться `result` с `ok=true`;
2. принять обновлённое уведомление `settings`, если изменялось конфигурационное поле;
3. принять следующий `status`, если изменялись `learnedCapacityWh`, `currentStoredWh` или `remainingPercent`;
4. показывать пользователю фактически полученное значение, поскольку прошивка может ограничить его допустимым диапазоном.
